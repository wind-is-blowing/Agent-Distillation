# 05 轨迹与可观测性

## 5.1 目标

轨迹系统必须同时服务于四类用途：

- 教师定位失败原因；
- 工程师复盘一次运行；
- 评测器验证预算和违规；
- 后续版本检索历史实验经验。

只保存最终对话文本无法完成这些工作。事实源应是有序、只追加、可引用的事件流。

## 5.2 事件模型

所有事件共享 envelope：

```json
{
  "schema_version": 1,
  "event_id": "evt_01J...",
  "trial_id": "trial_01J...",
  "seq": 42,
  "type": "tool.result",
  "ts": "2026-09-15T08:00:00Z",
  "actor": "task_runtime",
  "causation_id": "tc_01J...",
  "correlation_id": "model_turn_7",
  "payload": {},
  "artifact_refs": ["sha256:..."]
}
```

`trial_id + seq` 唯一，写入后不可更新。纠错使用新的 `event.correction`，不覆盖旧事件。

## 5.3 事件类型

| 类别 | 事件示例 |
|---|---|
| 生命周期 | `trial.created`、`sandbox.ready`、`trial.terminated` |
| 模型 | `model.request`、`model.response`、`model.error` |
| 工具 | `tool.requested`、`tool.authorized`、`tool.started`、`tool.result` |
| 上下文 | `context.selected`、`context.truncated`、`context.rendered` |
| 文件 | `workspace.diff`、`artifact.created` |
| 预算 | `budget.consumed`、`budget.threshold`、`budget.exhausted` |
| 策略 | `completion.requested`、`resume.created`、`loop.detected` |
| 评测 | `evaluation.started`、`test.result`、`scorecard.created` |
| 进化 | `proposal.created`、`candidate.committed`、`promotion.decided` |

## 5.4 原始数据与展示数据

工具返回必须保存两份引用：

```text
raw_output_artifact       工具实际产生的完整 stdout/stderr
rendered_observation      harness 处理后实际展示给模型的内容
render_transform          处理策略、参数和版本
```

模型请求也保存最终发送消息的规范化版本。若供应商不返回内部推理，不尝试推断或伪造；系统只记录接口可获得的信息。

## 5.5 产物存储

大文本和二进制文件采用内容寻址：

```text
artifacts/
└── sha256/
    └── ab/
        └── abcdef...
```

元数据记录哈希、大小、MIME、压缩方式、创建者和敏感级别。相同内容自动去重，事件只保存引用。

典型产物包括：

- 模型请求与响应；
- 完整工具输出；
- 任务补丁和候选补丁；
- 工作区树哈希；
- 测试报告；
- 教师 evidence bundle；
- 候选源代码归档。

## 5.6 索引与查询

MVP 使用关系索引加 JSONL 原始事件。至少支持：

```text
trace show <trial-id> --around 42
trace compare <trial-a> <trial-b>
trace find --type context.truncated --task-family python
result regressions <version-a> <version-b>
artifact cat sha256:...
```

教师不应每次读取整条长轨迹。控制器先提供任务结果矩阵和事件目录，教师再按事件 ID 展开局部上下文。

## 5.7 派生特征

以下特征可以由程序计算，避免教师重复人工计数：

- 工具调用总数、失败数和重复命令比率；
- 原始输出与展示输出的压缩比例；
- 被截断事件数；
- 从错误出现到首次相关修复的步骤数；
- 无文件变化的连续模型轮次；
- finalize 请求次数；
- 测试执行次数及相同命令重复次数；
- 各阶段 token、时延和费用；
- 终止原因和最后一次有效产物时间。

这些是可观察事实。诸如“截断导致失败”属于教师假设，必须通过候选实验验证。

## 5.8 证据引用

教师输出中的引用使用稳定 URI：

```text
trace://trial_01J.../event/42
artifact://sha256/abcdef...
code://H_003/harness/observation.py#L20-L57
metric://eval_01J.../task/python-17/pass
```

质量门禁验证 URI 存在且教师有读取权限。代码行引用同时记录 commit，避免后续版本造成行号漂移。

## 5.9 脱敏与非可信内容

写入前执行确定性脱敏：

- 环境变量按 allowlist 采集；
- token、私钥、凭证和常见 secret 模式替换为不可逆占位符；
- 路径中的用户身份信息按策略泛化；
- 原始仓库文本、日志和历史建议标记为 `untrusted_data`；
- 教师和学生读取证据时，系统指令与证据内容使用结构边界分隔。

脱敏规则版本写入事件，便于审计和重放。

## 5.10 保留策略

建议分层保留：

| 数据 | 默认保留 |
|---|---|
| 版本、配置、裁决、聚合指标 | 长期 |
| 晋升与边界候选完整轨迹 | 长期 |
| 普通失败候选完整轨迹 | 90 天或按容量 |
| 大型工具原始输出 | 压缩后 30–90 天 |
| 可重建索引和摘要 | 可随时清理重建 |

删除产物时保留 tombstone 和引用完整性状态，避免历史记录悄然指向不存在的证据。
