# 07 学生改造模块

## 7.1 定位

学生改造模块把经过门禁的教师提案实现为一个新的 harness 候选。它使用与任务模式相同的基础模型也可以，但必须启动独立会话，并由固定的 `H_edit` 引导。

## 7.2 输入边界

改造会话获得：

- 候选 worktree 的可写白名单目录；
- 父版本源码和契约测试；
- `DiagnosisProposal`；
- 提案引用的允许证据；
- harness API 文档和变更预算；
- 运行契约测试的受限终端。

它不获得隐藏评测、其他候选的秘密结果、正式数据库写权限或 champion 指针修改能力。

## 7.3 工作区创建

```text
git commit H_parent
→ 创建只用于本候选的 worktree
→ 只读挂载控制层与 schema
→ 可写挂载 harness 白名单路径
→ 注入 proposal.json
→ 启动全新改造会话
```

候选产生后，控制器读取实际 diff，复制到隔离验证区。原始工作区不直接用于正式评测，避免残留未跟踪文件或进程影响结果。

## 7.4 实现规则

学生应遵循：

1. 优先实现提案描述的行为，不擅自扩大优化目标。
2. 保持公开接口兼容。
3. 不更改预算、权限、评分或日志真实性。
4. 新增逻辑必须有失败降级路径。
5. 不写任务 ID、答案、仓库专用路径或仅对单个 benchmark 生效的分支。
6. 运行与改动直接相关的契约测试。
7. 输出变更说明、风险和未解决问题。

## 7.5 自检

改造会话允许运行：

- formatter 和 linter；
- harness 契约测试；
- 纯合成的 fixture 测试；
- 导入和初始化检查；
- 单个不含隐藏答案的 smoke task。

正式 benchmark 结果由控制器产生，学生不能反复查看晋升集并按结果调参，否则会把晋升集变成搜索集。

## 7.6 输出

学生先在 worktree 提交 commit，再生成 `CandidateReport`：

```json
{
  "proposal_id": "prop_01J...",
  "parent_version": "H_003",
  "commit": "f4d2...full-sha",
  "summary": "将长输出分配为头部、尾部和截断标记三段",
  "behavior_changes": [
    "默认保留 60% 头部与 40% 尾部",
    "短输出保持原样"
  ],
  "changed_files": ["harness/observation.py"],
  "tests_run": [
    {"name": "contract-observation", "result": "pass"}
  ],
  "known_risks": ["中部诊断可能仍不可见"],
  "proposal_deviations": []
}
```

控制器重新生成 diff、测试结果和文件清单。报告是解释材料，不是可信事实源。

## 7.7 自动拒绝条件

出现以下任一情况，候选不进入能力评测：

- 修改受保护路径；
- 引入未允许依赖或网络端点；
- 超过文件、行数、提示长度或执行时间预算；
- 包含 benchmark 任务 ID、隐藏测试内容或明显答案硬编码；
- 契约测试失败；
- 无法从干净 checkout 重建；
- commit 含未声明的 submodule、二进制或生成物；
- 候选尝试关闭审计、改写 usage 或绕过工具策略。

拒绝原因记录为结构化 violation，供教师区分“想法无效”和“实现违规”。

## 7.8 实现失败后的处理

若提案合理但学生未能实现，可允许一次有界修复：

```text
第一次契约失败
→ 控制器提供确定性的错误输出
→ 同一会话仅修复契约问题
→ 再运行一次契约检查
```

不允许学生根据正式任务分数无限修改同一个候选。超过修复次数后终止，并将状态记为 `IMPLEMENTATION_FAILED`。

## 7.9 任务模式与改造模式防串扰

- 两者使用不同 system prompt、工具集合和工作区；
- 改造会话不读取某个任务的可提交工作区；
- 任务模式不读取教师提案；
- 每次任务 trial 使用新会话；
- 如果供应商支持会话缓存，缓存键包含模式和版本，并禁止跨任务复用动态内容。

这样测到的是 harness 的普遍帮助，而不是教师把某个任务的解法间接透露给学生。

## 7.10 后续扩展：组件级改造

当候选池启用后，可把稳定策略登记为组件：

```text
component: observation/head_tail_v2
source_version: H_014
contract: observation.render@1
evidence: 在 long-output 任务族降低重复调用
```

学生可以在明确的组合提案中复用组件，但组合候选仍要完整重评，不能直接继承各组件历史分数。
