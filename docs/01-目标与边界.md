# 01 目标与边界

## 1.1 项目目标

本项目构建一个能够基于任务执行证据持续改进 Coding Agent harness 的实验与生产平台。系统每一轮都回答三个问题：

1. 当前 harness 在哪些任务上失败，模型当时实际看到了什么？
2. 哪一个可验证的 harness 改动最可能改善这些失败，同时保护已有能力？
3. 在固定比较条件下，新候选是否真的优于当前正式版本？

最终交付不是一个“会反思”的提示词，而是一套可复现的版本、实验和晋升体系。

## 1.2 优化对象

Harness 是位于模型与任务环境之间的可执行程序，负责：

- 组装系统提示、任务描述、仓库状态和历史消息；
- 注册工具并转换工具调用与返回；
- 管理上下文、任务状态、重试和完成协议；
- 在预算内决定何时继续、恢复、压缩或结束；
- 生成可供外部评分的任务产物。

任务仓库补丁与 harness 补丁必须严格区分：

| 产物 | 产生阶段 | 修改对象 | 生命周期 |
|---|---|---|---|
| `task_patch.diff` | 任务执行 | benchmark 目标仓库 | 单个 trial |
| `harness_patch.diff` | 自我改造 | harness 候选副本 | 一个候选版本 |

评测任务的答案、隐藏测试和评分器不属于搜索空间。

## 1.3 第一版目标

MVP 只验证受控闭环是否成立：

- 支持一种 Coding Agent runtime 和一种 benchmark adapter；
- 固定学生模型、模型参数与改造用 harness；
- 一个正式版本每轮产生一个挑战者；
- 教师每次提出一个主要假设；
- 学生只修改白名单文件；
- 候选经过契约检查、冒烟评测和晋升评测；
- 所有输入、输出、版本与裁决都可追溯；
- 中断后可以从最后一个稳定状态继续。

## 1.4 暂不进入 MVP 的能力

下列能力有价值，但会显著增加归因难度或系统复杂度：

- 多个模型角色共同辩论诊断；
- 学生模型权重训练或在线强化学习；
- 正在执行任务的进程热更新自身代码；
- harness 与改造 harness 同时共同演化；
- 大规模种群、遗传交叉和自动多目标调度；
- 无限制读取所有历史的长上下文方案；
- 由 LLM 自行修改评测规则或决定晋升。

这些能力只有在 MVP 能稳定复现实验、区分真实提升和噪声后再加入。

## 1.5 角色与权限

| 角色 | 允许 | 禁止 |
|---|---|---|
| 学生·任务模式 | 查看任务输入；操作任务工作区；调用任务工具；提交任务补丁 | 修改 harness、控制器、评分器；读取隐藏测试；继承其他 trial 工作区 |
| 教师·诊断模式 | 读取候选代码、分数、允许的轨迹与差异；提出证据化建议 | 修改任何代码；替学生完成任务；批准候选；更改预算和评分 |
| 学生·改造模式 | 在候选 worktree 中修改白名单 harness 文件；运行允许的自检 | 修改受保护文件；查看隐藏测试结果；将候选设为正式版本 |
| 控制器 | 创建隔离环境；调用角色；校验产物；触发评测；记录状态；执行确定性晋升规则 | 以自然语言印象替代评分规则 |
| 评测器 | 应用任务补丁；运行测试；计算指标；签名评测结果 | 接受候选代码提供的分数；向教师泄露隐藏答案 |

## 1.6 成功标准

项目成功必须同时满足能力、可信度和工程性。

### 能力

- 在至少一个保留任务族上，晋升版本相对基线有可重复提升；
- 提升不能完全由增加 token、工具调用或超时预算解释；
- 关键成功任务的回归率处于预设上限内。

### 可信度

- 任意分数可定位到版本、模型配置、任务快照、环境镜像和原始评测日志；
- 候选无法改写原始轨迹、预算统计或评分结果；
- 同一评测请求重试不会产生两个相互冲突的正式裁决。

### 工程性

- 一轮实验可以从配置文件启动，无需手工复制文件；
- 失败的 trial 不阻塞整轮，其状态和原因可见；
- 控制器异常退出后可以安全恢复；
- 支持停止、预算封顶和紧急禁用某个候选。

## 1.7 关键不变量

以下不变量应写入代码断言和验收测试：

1. 一个 trial 只绑定一个不可变 `harness_version_id`。
2. 正式评测启动后，候选 commit、任务快照和环境镜像摘要不可变化。
3. 原始事件只追加，不原地覆盖；派生摘要可重建。
4. 候选不能写入控制层、评测层或其他 trial 的工作区。
5. 晋升只能引用状态为 `EVALUATED` 且结果完整的候选。
6. 一个实验在任一时刻只有一个正式 champion；切换通过原子事务完成。
7. 最终测试集在搜索结束和选择规则冻结之前不可向教师或学生提供反馈。

## 1.8 威胁模型

系统处理三类风险：

- **无意错误**：提示词回归、上下文丢失、预算统计错误、环境漂移。
- **评测污染**：任务泄漏、跨 trial 缓存、搜索集与最终测试集混用。
- **非可信输入**：仓库文件、测试输出和历史轨迹包含诱导 Agent 越权的文本。

第 13 章给出权限和审计方案。本章的原则是：自然语言内容可以影响诊断与策略，但不能直接改变系统权限和裁决事实。
